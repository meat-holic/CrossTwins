# Internationalization (I18N)

This guide explains the UI locale system in CrossPoint Reader.

## Supported UI Languages

- English (`EN`)
- 한국어 (`KO`)

Other locale YAML files remain in the repository as translation references. They are not built
into the firmware or shown in the language picker. The language enum and native names remain
available for stable keyboard-layout labels and older settings migrations.

---


## For Developers

### Translation System Architecture

The I18N system uses **per-language YAML files** to maintain translations and a Python script to generate C++ code:

```
lib/I18n/
├── translations/                # One YAML file per language
│   ├── english.yaml
│   ├── spanish.yaml
│   ├── french.yaml
│   └── ...
├── I18n.h
├── I18n.cpp
├── I18nKeys.h                   # Enums (auto-generated)
├── I18nStrings.h                # String array declarations (auto-generated)
└── I18nStrings.cpp              # String array definitions (auto-generated)

scripts/
└── gen_i18n.py                  # Code generator script
```

**Key principle:** All translations are managed in the YAML files under `lib/I18n/translations/`. The Python script generates the necessary C++ code automatically.

---

### YAML File Format

Each language has its own file in `lib/I18n/translations/` (e.g. `spanish.yaml`).

A file looks like this:

```yaml
_language_name: "Español"
_language_code: "ES"
_order: "1"
_bcp47: "es"

STR_CROSSPOINT: "CrossPoint"
STR_BOOTING: "BOOTING"
STR_BROWSE_FILES: "Buscar archivos"
```

**Metadata keys** (prefixed with `_`):
- `_language_name` — Native display name retained for legacy enum and keyboard-layout labels
- `_language_code` — C++ enum name (e.g. "FR"). Please use the [ISO Code](https://en.wikipedia.org/wiki/List_of_ISO_639_language_codes) of the language. Must be a valid C++ identifier.
- `_order` — Historical metadata, still validated for uniqueness but no longer used to compute the `Language` enum order (see `_bcp47` below).
- `_bcp47` — [BCP 47](https://www.rfc-editor.org/rfc/rfc5646) language tag (e.g. `"pt-PT"`, `"ca-valencia"`). Must be unique. It controls the stable generated enum order. The visible Settings menu contains only built-in locales (English and Korean). Persisted preferences use `_language_code`, not the enum ordinal.

**Rules:**
- Use UTF-8 encoding
- Every line must follow the format: `KEY: "value"`
- Keys must be valid C++ identifiers (uppercase, starts with STR_)
- Keys must be unique within a file
- String values must be quoted
- Use `\n` for newlines, `\\` for literal backslashes, `\"` for literal quotes inside values

### Adding New Strings

To add a new translatable string:

#### 1. Edit the English YAML file

Add the key to `lib/I18n/translations/english.yaml`:

```yaml
STR_MY_NEW_STRING: "My New String"
```

Add the Korean translation to `lib/I18n/translations/korean.yaml`. Other locale
YAML files can remain unchanged; they are kept as reference material and are
not compiled into the firmware.

#### 2. Run the generator script

```bash
python3 scripts/gen_i18n.py lib/I18n/translations lib/I18n/
```

This automatically:
- Uses English for missing translations in the built-in locales
- Updates the `StrId` enum in `I18nKeys.h`
- Regenerates only built-in translation arrays in `I18nStrings.cpp` (English and Korean)

#### 3. Use in code

```cpp
#include <CrossPointSettings.h>
#include <I18n.h>
#include <Logging.h>

// Using the tr() macro (recommended)
renderer.drawText(font, x, y, tr(STR_MY_NEW_STRING));

// Using I18N.get() directly
const char* text = I18N.get(StrId::STR_MY_NEW_STRING);
```

**That's it!** No manual array synchronization needed.

### Locale YAML References

The existing non-English/non-Korean YAML files are retained but do not add
firmware UI language support. Expanding the built-in locale set requires an
explicit code change to `SUPPORTED_BUILTIN_LANGS` in `scripts/gen_i18n.py` and
the matching `custom_i18n_builtin_langs` value in `platformio.ini`.

---

### Modifying Existing Translations

Simply edit the relevant YAML file and regenerate:

```bash
python3 scripts/gen_i18n.py lib/I18n/translations lib/I18n/
```

---

### Built-in Locale Selection

The project builds English and Korean only, as configured in `platformio.ini`:

```ini
custom_i18n_builtin_langs = en,ko
```

The generator defaults to those two locales and rejects other built-in codes;
`all` also resolves to English and Korean. Other enum IDs and native names stay
available for keyboard labels and legacy settings migration. A removed locale in
saved settings resolves to English and is rewritten as `EN`.

The same selection can be passed to the generator directly:

```bash
python3 scripts/gen_i18n.py lib/I18n/translations lib/I18n/ --builtin-langs en,ko
```

An unsupported code is an error, so a typo or stale locale selection cannot silently
produce a different firmware configuration.

---

### UTF-8 Encoding

The YAML files use UTF-8 encoding. Special characters are automatically converted to C++ UTF-8 hex sequences by the generator.

### I18N API Reference

```cpp
// === Convenience Macros (Recommended) ===

// tr(id) - Get translated string without StrId:: prefix
const char* text = tr(STR_SETTINGS_TITLE);
renderer.drawText(font, x, y, tr(STR_BROWSE_FILES));
LOG_INF("I18N", "Status: %s", tr(STR_CONNECTED));

// I18N - Shorthand for I18n::getInstance()
I18N.setLanguage(Language::KO);
Language lang = I18N.getLanguage();

// === Full API ===

// Get the singleton instance
I18n& instance = I18n::getInstance();

// Get translated string (three equivalent ways)
const char* text = tr(STR_SETTINGS_TITLE);              // Macro (recommended)
const char* text = I18N.get(StrId::STR_SETTINGS_TITLE);   // Direct call
const char* text = I18N[StrId::STR_SETTINGS_TITLE];       // Operator overload

// Set runtime language
I18N.setLanguage(Language::KO);

// Get current language
Language lang = I18N.getLanguage();

// Get character set for font subsetting (static method)
const char* chars = I18n::getCharacterSet(Language::KO);

// Persist a user language choice
SETTINGS.language = static_cast<uint8_t>(Language::KO);
SETTINGS.saveToFile();
```

## File Storage

The selected language is stored with the rest of the device settings in:
```text
/.crosspoint/settings.json
```

The JSON field is `language`, stored as the stable code `"EN"` or `"KO"` rather
than a raw enum value. Removed or unknown codes are migrated to `"EN"`.

Older firmware versions used:
```text
/.crosspoint/language.bin
```

That legacy file is no longer read. Upgrading from a firmware old enough to
have written it resets the language to the default; re-select it once and it
persists in `settings.json`.

## Translation Workflow

### For Developers (Adding Features)

1. Add new strings to `lib/I18n/translations/english.yaml`
2. Run `python3 scripts/gen_i18n.py lib/I18n/translations lib/I18n/`
3. Use the new `StrId` in your code
4. Request translations from translators

### For Translators

1. Open the YAML file for your language in `lib/I18n/translations/`
2. Add or update translations using the format `STR_KEY: "translated text"`
3. Keep translations concise (E-ink space constraints)
4. Make sure the file is in UTF-8 encoding
5. Run `python3 scripts/gen_i18n.py lib/I18n/translations lib/I18n/` to verify
6. Test on device or submit for review
